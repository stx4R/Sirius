## 0. 한 줄 요약

플레이어는 5×5 성도(星圖)에 **남십자자리의 별 조각**을 놓아 **황도 12궁**을 완성하고,
딜러 **ORION(M42)**과 거래하며 덱을 강화한다.
매 순간의 선택은 **확률 판단**이며, 게임은 그 판단이 옳았는지를 **통계로 되돌려준다.**

### 1-2. ★ 중학생의 선수학습 (교과서가 직접 명시한 '배운 내용')

교과서는 각 대단원 도입부에 중학교 연계 내용을 명시한다. **이 게임의 난이도 기준선이다.**

| 학년 | 이미 배운 내용 | 게임에서 활용 |
|---|---|---|
| **중1** | 대푯값 / **도수분포표와 상대도수** | CONSTELLATION LOG의 상대도수 그래프 |
| **중2** | **경우의 수와 확률** | STAR-CHART, ORION'S WAGER의 기반 |
| **중3** | 산포도 / 상자그림과 산점도 | 점수 분포 시각화 |

> 🎯 **설계 원칙 확정**
> 중학생은 이미 **경우의 수·확률(중2)** 과 **상대도수(중1)** 를 배웠다.
> 따라서 이 게임은 *모르는 것을 가르치는 게* 아니라,
> **이미 아는 것(상대도수·확률)을 고교 개념(통계적 확률·기댓값)으로 잇는 다리**여야 한다.
> 부스에서 학생이 "아, 중학교 때 배운 그거네!"라고 말하게 만드는 것이 목표.

### 1-4. 교과서 반영 필수 수정 사항 ⚠️

교과서를 정독한 결과 **기존 설계에서 반드시 고쳐야 할 3가지**:

**① 용어 표기**
교과서는 **`큰수의 법칙`** 으로 붙여 쓴다(띄어쓰기 없음). 게임 내 모든 표기를 통일한다.
또한 이 개념은 확률 단원이 아니라 **Ⅲ-3 이항분포**의 학습 요소다.

**② `비복원추출`의 단원 위치**
조건부확률(Ⅱ-3)이 아니라 **Ⅲ-5 모집단과 표본**에 속한다.
따라서 STAR-CHART의 설명 문구는 "조건부확률"이 아니라 **"표본추출"** 맥락으로 쓴다.

**③ ★ 조건부확률 문제 설계 — 교과서의 명시적 경고**
교과서 지도상의 유의점은, 조건부확률을 **조건이 주어진 상황의 가능성**으로 이해시키되
**사건의 시간적 순서나 인과관계로 해석하지 않도록** 하라고 못박고 있다.

| | 문구 |
|---|---|
| ❌ **금지** | "Acrux가 **이미 3장 나갔다. 이제** Ginan이 더 나올까?" → 시간적 순서 유도 |
| ✅ **수정** | "**지금 덱이 이 상태일 때**, Ginan이 Acrux보다 많이 나올까?" → 조건 상태 제시 |

기존 8-2절의 라운드 6–8 예시 문구는 이 원칙에 따라 전량 재작성한다.

### 1-5. 게임 테마 문장

교과서 Ⅱ단원의 핵심 아이디어는 확률을 **합리적 의사 결정의 도구**로 규정한다.
이 문장이 STA-mble의 정체성과 정확히 일치하므로, **게임 타이틀 화면과 부스 배너의 태그라인**으로 사용한다.

> *"확률은 운을 예측하는 것이 아니라, 더 나은 선택을 하는 도구다."*

### 1-6. 보너스 소재 (선택)

교과서 Ⅱ단원 '미래 수학 유니버스'에 **몬티 홀 문제**가 실려 있다.
ORION의 특별 이벤트("세 개의 성운 중 하나에만 보상이 있다")로 재현하면
교과서와의 연계를 심사에서 직접 증명할 수 있다. → Phase 6에서 검토

## 3. 별자리 조각 (칩)

### 3-1. 기본 조각 5종

| ID | 이름 | 색 | 문양 | 기본 점수 |
|---|---|---|---|---|
| GAC | Gacrux | 연두 `#7FD44C` | 클로버 ♣ | 10 |
| IMA | Imai | 파랑 `#3F8FE0` | 다이아 ♦ | 10 |
| GIN | Ginan | 빨강 `#E0453F` | 하트 ♥ | 10 |
| MIM | Mimosa | 보라 `#9A4FD4` | X자 ✕ | 10 |
| ACR | Acrux | 검정 `#2B2B38` | 스페이드 ♠ | 10 |

**정산 순서(고정)**: Gacrux → Imai → Ginan → Mimosa → Acrux

### 3-2. 특수 별자리 조각 (₅C₂ = 10종)

두 문양을 반반 합친 칩. 정산 시 **두 문양 모두로 판정**되며, 양쪽 라인에 동시 기여한다.

**표기 규칙**: 좌/우는 **정산 순서(GAC → IMA → GIN → MIM → ACR)** 로 정규화한다.
즉 항상 순서가 앞선 문양이 `left`, 뒤선 문양이 `right`다. 중첩 루프 `i < j`로 10종이 자동 생성된다.

```
GAC&IMA  GAC&GIN  GAC&MIM  GAC&ACR
IMA&GIN  IMA&MIM  IMA&ACR
GIN&MIM  GIN&ACR
MIM&ACR
```

> 좌/우는 **시각적 배치에만** 영향을 준다(왼쪽 절반 색·문양). 정산은 두 문양을 대등하게 처리하므로
> 순서를 정규화해도 게임 로직에 변화가 없다. 초기 설계안 대비 3종의 좌우가 바뀐다
> (MIM&GAC → GAC&MIM, ACR&GAC → GAC&ACR, ACR&IMA → IMA&ACR).

**디자인 규칙**
- 칩 왼쪽 절반 = Something1의 색 / 오른쪽 절반 = Something2의 색
- 중앙 문양 = Something1 문양의 **왼쪽 절반** + Something2 문양의 **오른쪽 절반**을 이어 붙임

**획득**: ORION 상점에서만. 매 상점마다 10종 중 **랜덤 4종** 진열.

### 3-3. 떠돌이 별자리 조각 (1종, 게임당 1개 한정)

정산 시 인접 4방향 중 **랜덤 3방향**을 선택해, 그 방향에 있는 칩의 문양으로 **전부 판정**된다.

| 인접 칩 수 | 선택 방식 |
|---|---|
| 4개 | 랜덤 3방향 선택 (₄C₃ = 4가지, 각 1/4) |
| 3개 | 3개 전부 강제 선택 |
| 2개 | 2개 전부 강제 선택 |
| 1개 | 1개 강제 선택 |
| 0개 | 판정 없음 (0점) |

- 판정된 문양으로 **점수·라인 판정 모두** 참여한다.
- **중복 문양은 집합으로 합친다.** 선택된 3방향이 Gacrux·Gacrux·Ginan이면 결과는 {Gacrux, Ginan} 2종이다.
  떠돌이는 칸 하나를 차지하므로, 한 칸이 "Gacrux 2개"일 수는 없다. 라인 판정과 모순되지 않기 위한 필연적 규칙이다.
- **인접 칩이 특수 조각이면 두 문양을 모두 얻는다.** 특수 조각은 어디서든 두 문양 그 자체이므로 일관되게 처리한다.
  따라서 한 방향에서 2종을 얻을 수 있고, 3방향 전부 특수 조각이면 최대 5종(중복 제거 후)까지 가능하다.

> 🎯 **전술적 함의**: 집합 규칙 때문에 떠돌이는 **같은 문양이 몰린 곳보다 문양 경계에 놓을 때** 강하다.
> 별자리 시스템이 같은 문양 연속을 보상하는 것과 방향이 반대라, 배치 판단에 긴장이 생긴다.
- **판매 규칙**: 매 상점에 최대 1개만 진열. 플레이어가 1회 구매하면 이후 영구히 등장하지 않는다.

## 4. 보드 · 코어 루프

### 4-1. 구조

```
[게임 시작]
   └─ 라운드 1 ~ 8 반복
        ├─ 보드 초기화 (5×5 전부 비움) + 덱 전체 리셋 · 셔플
        ├─ 턴 1 ~ 5 반복
        │    ├─ ORION'S WAGER (예측 베팅) ── 선택제
        │    ├─ 덱에서 8장 드로우 (비복원)
        │    ├─ 손패 8장 중 최대 4장을 보드에 배치 → 즉시 고정
        │    ├─ 배치 안 한 조각은 덱으로 반환 후 셔플
        │    └─ 정산 → 라운드 누적 점수에 가산
        ├─ 누적 점수 ≥ 목표치 → 라운드 클리어 / 미달 → 게임 오버
        ├─ CONSTELLATION LOG (통계 리포트)
        └─ ORION 상점
```

## 5. 정산 알고리즘 (핵심)

### 5-1. 의사코드

```
총점 = 0
for 문양 in [GAC, IMA, GIN, MIM, ACR]:          # 고정 순서
    S = 보드 위에서 이 문양으로 판정되는 모든 칩
    if S 비어있음: continue

    발동라인들 = 보유 별자리로 탐색한 maximal 라인 전체

    for 라인 L in 발동라인들:
        라인배율 = Σ( L 조건을 만족시키는 보유 별자리들의 배율 )
        총점 += (L의 칩 수 × 10) × 라인배율

    비라인칩 = S 중 어떤 발동라인에도 속하지 않는 칩
    총점 += 비라인칩 수 × 10 × 1.0

    if 게자리 발동 and 이 문양이 최다 문양:
        총점 += S 전체 수 × 10 × 0.1
```

### 5-2. 배율 규칙 (확정)

| 규칙 | 내용 | 근거 ID |
|---|---|---|
| 스택 방식 | **단순 합산** — 세로 5연속 시 1.2 + 1.8 + 2.5 = **×5.5** | B-1, B-2 |
| 적용 범위 | **라인에 포함된 칩에만** 적용 (문양 전체 아님) | B-3 |
| 교차 중복 | 한 칩이 가로·세로 라인에 동시 포함되면 **양쪽에서 각각 계산** | B-4 |
| 라인 인정 | **maximal run만** (5연속 안의 3연속 부분집합을 따로 세지 않음) | 신규 확정 |
| 도형 중복 | **꼭짓점이 다르면 칸을 공유해도 각각 별개 라인** (ㅅ자·ㅗ자 포함) | 신규 확정 |
| 대각선 정의 | ↘·↗ 양방향 + 오프셋 대각선 전부 인정 | B-5 |

> 🔧 **튜닝 포인트**: 스택 방식(단순합 vs 곱연산 vs `1.0 + Σ(배율-1.0)`)은
> `src/core/config.ts`의 상수로 분리해 몬테카를로로 비교 검증할 것.

### 5-3. 계산 예시

Gacrux 5개가 1열에 세로 연속 배치 + 양자리·염소자리·궁수자리 보유

```
라인배율 = 1.2 + 1.8 + 2.5 = 5.5
점수     = (5칸 × 10점) × 5.5 = 275점
```

### 6-0. 배율 자료구조 (확정)

10종은 고정 배율, 2종(물병·처녀)은 패턴 크기에 따라 변동한다. 판별 유니온으로 통일한다.

```ts
type MultiplierSpec =
  | { kind: 'fixed';  value: number }
  | { kind: 'bySize'; table: Record<number, number> };   // key = 구성 칸 수
```

| 별자리 | 스펙 |
|---|---|
| 물병자리 | `bySize: { 3: 2.0, 5: 3.5 }` |
| 처녀자리 | `bySize: { 4: 1.5, 5: 1.9, 6: 2.2, 7: 2.5 }` |
| 나머지 10종 | `fixed: <표의 값>` |

`bySize`의 키는 서로 충돌하지 않으므로 칸 수만으로 배율이 유일하게 결정된다.
config는 **데이터만** 담는다 — 함수를 넣지 않는다(시뮬레이터가 값을 치환해야 하므로).

### 6-1. 'ㅅ'자 패턴 정의 (물병자리) — A-2 해소

꼭짓점 `(r, c)`에서 좌하 대각 n칸 + 우하 대각 n칸이 같은 문양으로 연속.

```
n = 1 (3칸)            n = 2 (5칸)
    ●                      ●
   ● ●                    ● ●
                         ●   ●
```

| n | 구성 칸 수 | 배율 | 5×5에서 가능한 위치 |
|---|---|---|---|
| 1 | 3 | ×2.0 | 다수 |
| 2 | 5 | ×3.5 | 꼭짓점이 (0,2)일 때만 |

### 6-2. 'ㅗ'자 패턴 정의 (처녀자리) — A-3 해소

가로 받침 m칸(연속) + 받침 **중앙**에서 위로 k칸.

| m (받침) | k (기둥) | 구성 칸 수 | 배율 |
|---|---|---|---|
| 3 | 1 | 4 | ×1.5 |
| 3 | 2 | 5 | ×1.9 |
| 5 | 1 | 6 | ×2.2 |
| 5 | 2 | 7 | ×2.5 |

### 6-3. 게자리 특례 — B-7 해소

- 보드에서 **가장 많이 배치된 문양**에 적용
- 동점 시 해당 문양 **전부** 발동
- 유일하게 **라인이 아닌 문양 전체**에 적용되는 별자리 (+10% 가산)

## 11. 아트 파이프라인 (프로시저럴 생성 방식 확정)

### 11-1. 방식

**이미지 파일을 만들지 않는다.** 픽셀맵을 코드로 정의하고 런타임에 생성한다.

```
픽셀맵 정의 (16×16 배열)
   → 오프스크린 Canvas 16×16에 1px 단위로 그림
   → toDataURL()로 1회 변환 후 useMemo 캐시
   → <img> 로 표시, CSS width:32px + image-rendering:pixelated
```

16px 원본을 정수 2배로 확대하므로 **완벽한 도트 룩**이 나오고, rect를 수천 개 그리는 성능 문제도 없다.

### 11-2. 이 방식을 택한 결정적 이유 — 특수 조각 10종

특수 별자리 조각은 두 문양을 반반 합친 것이다. 손으로 그리면 **10장을 따로 그려야 한다.**
픽셀맵이 코드에 있으면 **합성 함수 하나로 10종이 자동 생성된다.**

```ts
// 개념
function composeSpecial(a: SuitId, b: SuitId): PixelMap {
  const left  = PIXELS[a].map(row => row.slice(0, 8));   // A 문양 좌측 8열
  const right = PIXELS[b].map(row => row.slice(8, 16));  // B 문양 우측 8열
  return left.map((row, i) => [...row, ...right[i]]);
}
// 배경색도 좌/우 분할하여 동일하게 합성
```

기본 5종만 그리면 특수 10종은 공짜다. 색을 바꾸고 싶으면 상수 하나만 고치면 된다.

### 11-3. 파일 구조

| 파일 | 내용 |
|---|---|
| `src/assets/palette.ts` | 32색 팔레트 상수 |
| `src/assets/pixels.ts` | 문양 5종 + ORION + UI 아이콘의 픽셀맵 |
| `src/assets/compose.ts` | 특수 조각 합성 함수 |

## 12. 부스 운영 제약 ⚠️ (1인 운영 확정)

개발자 겸 운영자가 **1명**이다. 이는 게임 설계에 직접 영향을 준다.

### 12-1. 처리량 계산

| 조건 | 시간당 참여자 |
|---|---|
| 풀버전 40분 × 노트북 1대 | **1.5명** |
| 풀버전 40분 × 노트북 3대 | 4.5명 |
| 부스판 15분 × 노트북 3대 | **12명** |

GBL은 **참여 중학생의 투표**로 순위가 정해진다.
표를 던질 사람 수가 곧 점수이므로, **처리량이 곧 성적**이다.

### 12-2. 그래서 필요한 것

1. **완전 자립형 튜토리얼** — 운영자가 옆에 붙어 설명하지 않아도 시작할 수 있어야 한다.
   1인 운영에서는 이게 선택이 아니라 필수다.
2. **노트북 3대 이상 동시 운영** — 브라우저 실행이므로 대수 확장은 자유롭다.
3. **부스판(3라운드 ≈ 15분) 분기** — Phase 7에서 최종 판단.
   풀버전 코드에서 `TOTAL_ROUNDS`와 `TARGET_SCORES`만 교체하면 되도록 설계한다.
4. **원클릭 리셋** — 다음 참여자를 위해 즉시 초기화.
5. **로컬 리더보드** — 운영자 개입 없이 경쟁 심리 유발.

### 12-3. 설계 반영

`src/core/config.ts`에 부스 모드 프리셋을 함께 정의한다.

```ts
export const MODE_PRESETS = {
  full:  { TOTAL_ROUNDS: 8, TARGET_SCORES: [300, 500, 800, 1300, 2100, 3400, 5500, 9000] },
  booth: { TOTAL_ROUNDS: 3, TARGET_SCORES: [300, 500, 800] },
};
```

### 12-4. 부스 모드의 밸런스 철학은 풀버전과 정반대다

| | 풀버전 | 부스판 |
|---|---|---|
| 목표 클리어율 | **20 ~ 30%** (도전) | **70% 이상** (만족) |
| 최적화 대상 | 재도전 욕구 | **투표** |

부스 참여자는 단 한 번 플레이하고 투표한다. 실패하고 떠나면 표를 잃는다.
따라서 부스판 목표치는 풀버전 1~3라운드 값을 그대로 쓰되,
**P2 시뮬레이션에서 클리어율이 70% 미만이면 하향 조정**한다. 상향은 하지 않는다.

**① 단일 문양 도배 보드 + 물병자리·처녀자리 동시 보유**
꼭짓점이 다르면 별개 라인이므로, 5×5를 한 문양으로 채우면

**② 떠돌이 조각 + 특수 조각 3개 인접**
한 칸이 최대 5종 판정을 받는 최상위 시너지. 20 스타더스트 가격이 맞는지 확인한다.
