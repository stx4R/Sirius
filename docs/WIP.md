### 품절 처리가 core에 있는 이유 — 되돌리지 말 것

`buy`가 산 물건을 `game.stock`에서 뺀다. UI가 아니라 core인 이유는 **밸런스**다:
P2-B의 목표 곡선은 각 진열 품목을 최대 1회 사는 상점 정책(`sim/player.ts`)으로 측정됐다.

**시뮬레이터가 영향을 받지 않는다는 것은 실측했다** — greedy·smart × 시드 1~25,
8라운드 완주 50게임의 클리어 수·스타더스트·라운드 점수가 변경 전후 **완전히 동일**했다.
`buy`는 rng를 소비하지 않고, `playGame`은 구매 목록을 미리 계산하므로 stock 변화를 읽지 않는다.

**거절된 구매는 진열에 남는다.** `applyPurchase`가 거절할 때 같은 loadout을 그대로
돌려주므로(참조 동일) `buy`가 그것으로 판별한다. 이 규약을 깨면 품절 판정이 틀어진다.

### иєвυℓα 스프라이트 — 1차 리뷰에서 통째로 다시 만들었다

**초안은 로켓/촛불로 읽혔다.** 큰 후드 타원 + 검은 얼굴 구멍 + 매끈한 원뿔 로브였다.
지금은 **인간형 골격을 분명히 하고** 흩어지는 쪽으로 대비를 준다 (GDD 11-9 개정):
후드 머리(높이 1/4) → 목 → 어깨 → **소매 2개** → 허리 → 로브 → 밑단이 가닥으로 소멸.

**★ 되돌리면 안 되는 세 가지 — 전부 실제로 실패해서 알아낸 것이다**

| # | 규칙 | 어겼을 때 |
|---|---|---|
| 1 | 픽셀·열 단위 난수 금지. **저주파 사인파만** | 1px 가시가 서서 밑단이 잡티가 된다 |
| 2 | 어깨 아래 좌우 대칭 금지. 흔들림은 **`x` 기준**(`|x−중심|` 아님) | 완전 대칭 원뿔 = **로켓 노즐** |
| 3 | 후드 안을 `void`로 칠하지 말 것 | 얼굴 모양 **관통상**으로 읽힌다 |

추가로 배운 것 두 가지:
- **팔은 윤곽만으로 안 읽힌다.** 소매를 로브보다 한 톤 밝게(`NEBULA_INK.sleeve`) 칠해야
  팔이 "옷 주름"이 아니라 별개 형태가 된다
- **베일이 너무 어두우면 캐릭터가 검은 실루엣이 된다.** 초안의 `veil`은 luma 47이라
  보라가 전혀 안 보였다. 지금 0.30/0.39/0.46 세 단계(luma 65/78/87)

### 확정된 결정 (다시 묻지 말 것)

1. core breakdown(`bySuit` + `cells`) 승인됨.
2. **"전체 배율" 칸 없음.** GDD 5-2는 배율을 라인 단위로만 스택한다.
3. **문양별 "×배율"도 합치지 않는다.** 발동 라인 배율을 그대로 나열.
4. `ORION'S WAGER` 명칭 유지. **иєвυℓα 표기 그대로 노출.**
5. **대사 RNG는 `game.rng`와 분리.** ORION `seed ^ 0x5ee0`, иєвυℓα `seed ^ 0x2eb0`.
   게임 RNG를 소비하면 시드 재현이 깨진다.
6. `dialogue.ts`는 `src/ui/`. **store는 import하지 않는다**(store→ui는 역방향).
7. 레이아웃은 고정 캔버스. 8. 배율은 정수 내림.
9. **иєвυℓα는 눈이 있다.** 초안의 "얼굴 없음"은 리뷰에서 뒤집혔다 — 구멍이 아니라
   그림자 속의 시선이어야 한다. GDD 11-9를 그렇게 개정했다.
10. **`AnimatePresence mode="wait"` 금지.** 프레임이 밀리면 새 요소를 아예 마운트하지
   않아 내용이 통째로 사라진다. 상태 텍스트·말풍선에서 두 번 재현했고, 화면 전환도
   같은 이유로 **입장 애니메이션만** 쓴다(exit 없음).
11. **품절은 core**, **덱 집계는 `core/deck.ts`** — 둘 다 사용자 승인 완료 (P4-A).

### ★ 동반성 봉인 — P4-B 전까지 절대 풀지 말 것

P2-B의 목표 곡선은 **전부 "동반성 없음" 기준**이다(GDD 13-6). 하나라도 상태에 새면 무효가 된다.

**런타임 가드가 아니라 타입으로 막혀 있다**: `core/shop.ts`의 `Purchase` 유니온에
`companion` 변형이 **없다.** 동반성 구매는 값으로 표현조차 되지 않는다.
→ **P4-B는 이 변형을 추가하는 것에서 시작한다.** (GDD 미해결 #23)

상점 화면은 동반성을 **진열하되 팔지 않는다**. 슬롯은 티어·공개 확률·가격을 다 인쇄하고
(GDD 7-1의 확률 공개는 교육 장치다) 누르면 иєвυℓα가 `locked` 대사로 이유를 말한다.
`tests/shop.test.ts`의 `describe('companions are stocked but never owned (P4-A)')`가
8라운드 완주 중 `ownedCompanions`가 항상 빈 배열임을 검사한다.

## 3. 화면을 보는 방법 — `npm run shot`

Claude 브라우저 확장은 이 환경에서 연결되지 않고, 저장소에 jsdom도 없다.
그래서 `tools/screenshot.mjs`를 뒀다. **헤드리스 Chrome을 DevTools 프로토콜로 몰아
실제 DOM을 클릭해 플레이한다** — 상태를 주입하지 않으므로 찍히는 건 진짜 화면이다.

```
npm run dev            # 한쪽 터미널
npm run shot -- shots  # 다른 쪽. shots/ 는 gitignore 대상
```

**교체 프롬프트가 특히 이것 없이는 못 본다** — 별자리 4개 보유 + 5번째 구매 시도라는
조건이라, 손으로 가려면 두 라운드를 완주해야 한다. 스크립트는 DEV 패널로 별자리를

좌표를 고칠 때는 `SHOP_LAYOUT`이 정본이고 **GDD 11-10 표도 같이 고칠 것**(표는 사본이다).
