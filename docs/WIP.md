### 1-a. MODE_ORDER 분기 — 빌드 시점이다

`Title.tsx`의 `modeOrder(prod, unlocked)`가 순수 함수이고, 호출부가
`modeOrder(import.meta.env.PROD, fullUnlocked())` 하나다.

| 환경 | 보이는 모드 | 이유 |
|---|---|---|
| `npm run dev` | 부스판 + 풀버전 | 개발·`npm run shot`이 두 모드를 다 쓴다. 켜야 할 플래그가 없다 |
| 프로덕션 빌드 (부스 노트북) | **부스판만** | 풀버전 8라운드 ≈ 40분. 12-1절 기준 좌석 하나가 표 하나를 잃는다 |
| 프로덕션 빌드 + `?mode=full` | 부스판 + 풀버전 | 시연·검증용. 학생이 우연히 칠 수 없다 |

**런타임 설정(`.env`·`localStorage`)을 쓰지 않은 이유**: 부스 노트북이 3~5대이고
운영자가 1명이다. 대당 설정이 필요한 방식은 **한 대만 잘못 켜져 있어도 그 좌석이 40분
점유되고**, 그것을 알아채는 사람이 없다. `import.meta.env.PROD`는 배포 산출물 자체가
결정하므로 대당 편차가 생길 수 없다. `?seed=`(`gameStore.ts`)가 이미 같은 방식의
탈출구이므로 규약도 새로 만들지 않았다.

### 품절 처리가 core에 있는 이유 — 되돌리지 말 것

`buy`가 산 물건을 `game.stock`에서 뺀다. UI가 아니라 core인 이유는 **밸런스**다:
P2-B의 목표 곡선은 각 진열 품목을 최대 1회 사는 상점 정책(`sim/player.ts`)으로 측정됐다.

**시뮬레이터가 영향을 받지 않는다는 것은 실측했다** — greedy·smart × 시드 1~25,
8라운드 완주 50게임의 클리어 수·스타더스트·라운드 점수가 변경 전후 **완전히 동일**했다.

**거절된 구매는 진열에 남는다.** `applyPurchase`가 거절할 때 같은 loadout을 그대로
돌려주므로(참조 동일) `buy`가 그것으로 판별한다. 이 규약을 깨면 품절 판정이 틀어진다.

### 확정된 결정 (다시 묻지 말 것)

1. core breakdown(`bySuit` + `cells`) 승인됨.
2. **"전체 배율" 칸 없음.** GDD 5-2는 배율을 라인 단위로만 스택한다.
3. **문양별 "×배율"도 합치지 않는다.** 발동 라인 배율을 그대로 나열.
4. `ORION'S WAGER` 명칭 유지. **иєвυℓα 표기 그대로 노출.**
5. **대사 RNG는 `game.rng`와 분리.** ORION `seed ^ 0x5ee0`, иєвυℓα `seed ^ 0x2eb0`.
   게임 RNG를 소비하면 시드 재현이 깨진다.
6. `dialogue.ts`는 `src/ui/`. **store는 import하지 않는다**(store→ui는 역방향).
7. 레이아웃은 고정 캔버스. 8. 배율은 정수 내림.
9. **иєвυℓα는 눈이 있다.** 구멍이 아니라 그림자 속의 시선 (GDD 11-9).
10. **`AnimatePresence mode="wait"` 금지.** 프레임이 밀리면 새 요소를 아예 마운트하지
    않아 내용이 통째로 사라진다. 상태 텍스트·말풍선에서 두 번 재현했고, 화면 전환도
    같은 이유로 **입장 애니메이션만** 쓴다(exit 없음).
11. **품절은 core**, **덱 집계는 `core/deck.ts`** — 둘 다 사용자 승인 완료 (P4-A).
12. **코치마크는 "런의 1라운드"** 판정이다 (GDD 12-2-a). `localStorage`도 페이지 로드
    플래그도 아니다 — **중도 리셋 뒤 다음 학생이 튜토리얼을 놓치지 않게 하는 것**이
    이 판정의 존재 이유이고, `tests/booth.test.ts`가 그것을 고정한다.
13. **중도 리셋에는 확인 단계가 있다.** 버튼이 `?` 바로 옆이라 오조작이 실제 위험이고,
    한 번의 오조작이 20분을 날린다. `계속하기`가 강조 버튼인 것도 같은 이유다.

## 3. 화면을 보는 방법 — `npm run shot`

Claude 브라우저 확장은 이 환경에서 연결되지 않고, 저장소에 jsdom도 없다.
그래서 `tools/screenshot.mjs`를 뒀다. **헤드리스 Chrome을 DevTools 프로토콜로 몰아
실제 DOM을 클릭해 플레이한다** — 상태를 주입하지 않으므로 찍히는 건 진짜 화면이다.

```
npm run dev            # 한쪽 터미널
npm run shot -- shots  # 다른 쪽. shots/ 는 gitignore 대상
```

**27장**이 나온다: `title` · `coach-*`(5) · `game` · `help` · `reset-confirm` · `orion` ·
`wager*`(4) · `oracle*`(3) · `report-round1/3` · `shop` · `shop-gift` · `shop-replace` ·
`nebula` · `end-cleared` · `end-gameover` · `orion-moods` · `orion-zoom`.

**손으로는 못 보는 것이 이 도구의 존재 이유다** — 교체 프롬프트(별자리 4개 + 5번째 구매),
떠돌이 지급 대사(런당 1회), 게임오버 배너(핀 시드는 매 라운드 클리어하므로 **일부러
포기하는 두 번째 런**을 따로 돈다).

**스크린샷이 조용히 실패하지 않게 하는 장치가 여럿 있다** — 빈 PNG 바이트 검사,
길이가 같은 두 PNG = 같은 이미지 판정, 패널 `scrollHeight`/`clientHeight` 잘림 실측,
그리고 이름과 실제 화면이 다르면 실패로 기록(`data-coach` / `data-panel` 조회).
**성공 판정은 로그 마지막 줄이 아니라 exit 코드다.**

좌표를 고칠 때는 `LAYOUT`/`SHOP_LAYOUT`이 정본이고 **GDD 11-10 표도 같이 고칠 것**(표는 사본이다).
