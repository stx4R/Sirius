플레이어는 5×5 성도(星圖)에 **남십자자리의 별 조각**을 놓아 **황도 12궁**을 완성하고,

매 순간의 선택은 **확률 판단**이며, 게임은 그 판단이 옳았는지를 **통계로 되돌려준다.**

> **이미 아는 것(상대도수·확률)을 고교 개념(통계적 확률·기댓값)으로 잇는 다리**여야 한다.
> 부스에서 학생이 "아, 중학교 때 배운 그거네!"라고 말하게 만드는 것이 목표.

### 1-4. 교과서 반영 필수 수정 사항 ⚠️

교과서를 정독한 결과 **기존 설계에서 반드시 고쳐야 할 3가지**:

**① 용어 표기**
교과서는 **`큰수의 법칙`** 으로 붙여 쓴다(띄어쓰기 없음). 게임 내 모든 표기를 통일한다.
또한 이 개념은 확률 단원이 아니라 **Ⅲ-3 이항분포**의 학습 요소다.

**② `비복원추출`의 단원 위치**
조건부확률(Ⅱ-3)이 아니라 **Ⅲ-5 모집단과 표본**에 속한다.
따라서 STAR-CHART의 설명 문구는 "조건부확률"이 아니라 **"표본추출"** 맥락으로 쓴다.

**③ ★ 조건부확률 문제 설계 — 교과서의 명시적 경고**
교과서 지도상의 유의점은, 조건부확률을 **조건이 주어진 상황의 가능성**으로 이해시키되
**사건의 시간적 순서나 인과관계로 해석하지 않도록** 하라고 못박고 있다.

| | 문구 |
|---|---|
| ❌ **금지** | "Acrux가 **이미 3장 나갔다. 이제** Ginan이 더 나올까?" → 시간적 순서 유도 |
| ✅ **수정** | "**지금 덱이 이 상태일 때**, Ginan이 Acrux보다 많이 나올까?" → 조건 상태 제시 |

기존 8-2절의 라운드 6–8 예시 문구는 이 원칙에 따라 전량 재작성한다.

### 1-5. 게임 테마 문장

교과서 Ⅱ단원의 핵심 아이디어는 확률을 **합리적 의사 결정의 도구**로 규정한다.
이 문장이 STA-mble의 정체성과 정확히 일치하므로, **게임 타이틀 화면과 부스 배너의 태그라인**으로 사용한다.

> *"확률은 운을 예측하는 것이 아니라, 더 나은 선택을 하는 도구다."*

### 1-6. 보너스 소재 (선택)

교과서 Ⅱ단원 '미래 수학 유니버스'에 **몬티 홀 문제**가 실려 있다.
ORION의 특별 이벤트("세 개의 성운 중 하나에만 보상이 있다")로 재현하면
교과서와의 연계를 심사에서 직접 증명할 수 있다. → Phase 6에서 검토

## 3. 별자리 조각 (칩)

### 3-1. 기본 조각 5종

| ID | 이름 | 색 | 문양 | 기본 점수 |
|---|---|---|---|---|
| GAC | Gacrux | 연두 `#7FD44C` | 클로버 ♣ | 10 |
| IMA | Imai | 파랑 `#3F8FE0` | 다이아 ♦ | 10 |
| GIN | Ginan | 빨강 `#E0453F` | 하트 ♥ | 10 |
| MIM | Mimosa | 보라 `#9A4FD4` | X자 ✕ | 10 |
| ACR | Acrux | 검정 `#2B2B38` | 스페이드 ♠ | 10 |

**정산 순서(고정)**: Gacrux → Imai → Ginan → Mimosa → Acrux

### 3-2. 특수 별자리 조각 (₅C₂ = 10종)

두 문양을 반반 합친 칩. 정산 시 **두 문양 모두로 판정**되며, 양쪽 라인에 동시 기여한다.

**표기 규칙**: 좌/우는 **정산 순서(GAC → IMA → GIN → MIM → ACR)** 로 정규화한다.
즉 항상 순서가 앞선 문양이 `left`, 뒤선 문양이 `right`다. 중첩 루프 `i < j`로 10종이 자동 생성된다.

```
GAC&IMA  GAC&GIN  GAC&MIM  GAC&ACR
IMA&GIN  IMA&MIM  IMA&ACR
GIN&MIM  GIN&ACR
MIM&ACR
```

> 좌/우는 **시각적 배치에만** 영향을 준다(왼쪽 절반 색·문양). 정산은 두 문양을 대등하게 처리하므로
> 순서를 정규화해도 게임 로직에 변화가 없다. 초기 설계안 대비 3종의 좌우가 바뀐다
> (MIM&GAC → GAC&MIM, ACR&GAC → GAC&ACR, ACR&IMA → IMA&ACR).

**디자인 규칙**
- 칩 왼쪽 절반 = Something1의 색 / 오른쪽 절반 = Something2의 색
- 중앙 문양 = Something1 문양의 **왼쪽 절반** + Something2 문양의 **오른쪽 절반**을 이어 붙임

**획득**: иєвυℓα 상점에서만. 매 상점마다 10종 중 **랜덤 4종** 진열.

### 3-3. 떠돌이 별자리 조각 (1종, 게임당 1개 한정)

정산 시 인접 4방향 중 **랜덤 3방향**을 선택해, 그 방향에 있는 칩의 문양으로 **전부 판정**된다.

| 인접 칩 수 | 선택 방식 |
|---|---|
| 4개 | 랜덤 3방향 선택 (₄C₃ = 4가지, 각 1/4) |
| 3개 | 3개 전부 강제 선택 |
| 2개 | 2개 전부 강제 선택 |
| 1개 | 1개 강제 선택 |
| 0개 | 판정 없음 (0점) |

- 판정된 문양으로 **점수·라인 판정 모두** 참여한다.
- **중복 문양은 집합으로 합친다.** 선택된 3방향이 Gacrux·Gacrux·Ginan이면 결과는 {Gacrux, Ginan} 2종이다.
  떠돌이는 칸 하나를 차지하므로, 한 칸이 "Gacrux 2개"일 수는 없다. 라인 판정과 모순되지 않기 위한 필연적 규칙이다.
- **인접 칩이 특수 조각이면 두 문양을 모두 얻는다.** 특수 조각은 어디서든 두 문양 그 자체이므로 일관되게 처리한다.
  따라서 한 방향에서 2종을 얻을 수 있고, 3방향 전부 특수 조각이면 최대 5종(중복 제거 후)까지 가능하다.

> 🎯 **전술적 함의**: 집합 규칙 때문에 떠돌이는 **같은 문양이 몰린 곳보다 문양 경계에 놓을 때** 강하다.
> 별자리 시스템이 같은 문양 연속을 보상하는 것과 방향이 반대라, 배치 판단에 긴장이 생긴다.
- **지급 규칙**: 판매하지 않는다. **иєвυℓα와의 첫 만남에서 1개를 무상 지급**하고, 이후 다시 등장하지 않는다 (13-4절).

## 4. 보드 · 코어 루프

### 4-1. 구조

```
[게임 시작]
   └─ 라운드 1 ~ 8 반복
        ├─ 보드 초기화 (5×5 전부 비움) + 덱 전체 리셋 · 셔플

        │    ├─ 배치 안 한 조각은 덱으로 반환 후 셔플
        │    └─ 정산 → 라운드 누적 점수에 가산

        └─ иєвυℓα 상점
```

## 5. 정산 알고리즘 (핵심)

### 5-1. 의사코드

```
총점 = 0
for 문양 in [GAC, IMA, GIN, MIM, ACR]:          # 고정 순서
    S = 보드 위에서 이 문양으로 판정되는 모든 칩
    if S 비어있음: continue

    발동라인들 = 보유 별자리로 탐색한 maximal 라인 전체

    for 라인 L in 발동라인들:
        라인배율 = Σ( L 조건을 만족시키는 보유 별자리들의 배율 )
        총점 += (L의 칩 수 × 10) × 라인배율

    비라인칩 = S 중 어떤 발동라인에도 속하지 않는 칩
    총점 += 비라인칩 수 × 10 × 1.0

    if 게자리 발동 and 이 문양이 최다 문양:
        총점 += S 전체 수 × 10 × 0.1
```

### 5-2. 배율 규칙 (확정)

| 규칙 | 내용 | 근거 ID |
|---|---|---|
| 스택 방식 | **단순 합산** — 세로 5연속 시 1.2 + 1.8 + 2.5 = **×5.5** | B-1, B-2 |
| 적용 범위 | **라인에 포함된 칩에만** 적용 (문양 전체 아님) | B-3 |
| 교차 중복 | 한 칩이 가로·세로 라인에 동시 포함되면 **양쪽에서 각각 계산** | B-4 |
| 라인 인정 | **maximal run만** (5연속 안의 3연속 부분집합을 따로 세지 않음) | 신규 확정 |
| 도형 중복 | **꼭짓점이 다르면 칸을 공유해도 각각 별개 라인** (ㅅ자·ㅗ자 포함) | 신규 확정 |
| 대각선 정의 | ↘·↗ 양방향 + 오프셋 대각선 전부 인정 | B-5 |

> 🔧 **튜닝 포인트**: 스택 방식(단순합 vs 곱연산 vs `1.0 + Σ(배율-1.0)`)은

### 6-0. 배율 자료구조 (확정)

10종은 고정 배율, 2종(물병·처녀)은 패턴 크기에 따라 변동한다. 판별 유니온으로 통일한다.

```ts
type MultiplierSpec =
  | { kind: 'fixed';  value: number }
  | { kind: 'bySize'; table: Record<number, number> };   // key = 구성 칸 수
```

| 별자리 | 스펙 |
|---|---|
| 물병자리 | `bySize: { 3: 2.0, 5: 3.5 }` |
| 처녀자리 | `bySize: { 4: 1.5, 5: 1.9, 6: 2.2, 7: 2.5 }` |
| 나머지 10종 | `fixed: <표의 값>` |

`bySize`의 키는 서로 충돌하지 않으므로 칸 수만으로 배율이 유일하게 결정된다.
config는 **데이터만** 담는다 — 함수를 넣지 않는다(시뮬레이터가 값을 치환해야 하므로).

### 6-1. 'ㅅ'자 패턴 정의 (물병자리) — A-2 해소

꼭짓점 `(r, c)`에서 좌하 대각 n칸 + 우하 대각 n칸이 같은 문양으로 연속.

```
n = 1 (3칸)            n = 2 (5칸)
    ●                      ●
   ● ●                    ● ●
                         ●   ●
```

| n | 구성 칸 수 | 배율 | 5×5에서 가능한 위치 |
|---|---|---|---|
| 1 | 3 | ×2.0 | 다수 |
| 2 | 5 | ×3.5 | 꼭짓점이 (0,2)일 때만 |

### 6-2. 'ㅗ'자 패턴 정의 (처녀자리) — A-3 해소

| m (받침) | k (기둥) | 구성 칸 수 | 배율 |
|---|---|---|---|
| 3 | 1 | 4 | ×1.5 |
| 3 | 2 | 5 | ×1.9 |
| 5 | 1 | 6 | ×2.2 |
| 5 | 2 | 7 | ×2.5 |

### 6-3. 게자리 특례 — B-7 해소

- 보드에서 **가장 많이 배치된 문양**에 적용
- 동점 시 해당 문양 **전부** 발동
- 유일하게 **라인이 아닌 문양 전체**에 적용되는 별자리 (+10% 가산)

| 개념 노출 | 별자리 배율이 R1부터 실제로 발동한다 |

### 10-3. 시작 별자리는 밸런스의 전제였다

피드백 장치로 도입했으나, 측정 결과 **없으면 어떤 곡선으로도 조건 2를 만족할 수 없다.**

| (sum 기준) | 시작 별자리 없음 | 있음 |
|---|---|---|
| greedy 부스판 클리어율 | 62.1% | **85.3%** |
| smart 풀버전 클리어율 | 18.8% | **28.1%** |
| R1 표준편차 | 0 | **28** |

## 11. 아트 파이프라인 (프로시저럴 생성 방식 확정)

### 11-1. 방식

**이미지 파일을 만들지 않는다.** 픽셀맵을 코드로 정의하고 런타임에 생성한다.

```
픽셀맵 정의 (16×16 배열)
   → 오프스크린 Canvas 16×16에 1px 단위로 그림
   → toDataURL()로 1회 변환 후 useMemo 캐시
   → <img> 로 표시, CSS width:32px + image-rendering:pixelated
```

16px 원본을 정수 2배로 확대하므로 **완벽한 도트 룩**이 나오고, rect를 수천 개 그리는 성능 문제도 없다.

### 11-2. 이 방식을 택한 결정적 이유 — 특수 조각 10종

특수 별자리 조각은 두 문양을 반반 합친 것이다. 손으로 그리면 **10장을 따로 그려야 한다.**
픽셀맵이 코드에 있으면 **합성 함수 하나로 10종이 자동 생성된다.**

```ts
// 개념
function composeSpecial(a: SuitId, b: SuitId): PixelMap {
  const left  = PIXELS[a].map(row => row.slice(0, 8));   // A 문양 좌측 8열
  const right = PIXELS[b].map(row => row.slice(8, 16));  // B 문양 우측 8열
  return left.map((row, i) => [...row, ...right[i]]);
}
// 배경색도 좌/우 분할하여 동일하게 합성
```

기본 5종만 그리면 특수 10종은 공짜다. 색을 바꾸고 싶으면 상수 하나만 고치면 된다.

### 11-3. 파일 구조

| 파일 | 내용 |
|---|---|
| `src/assets/palette.ts` | 32색 팔레트 상수 |
| `src/assets/pixels.ts` | 문양 5종 + **별자리 아이콘 12종** + 떠돌이 + ORION + UI 아이콘의 픽셀맵 |
| `src/assets/compose.ts` | 특수 조각 합성 함수 |
| `src/ui/PixelSprite.tsx` | 픽셀맵 → Canvas → dataURL 렌더 컴포넌트 |

### 11-4. 규격

| 대상 | 원본 픽셀맵 | 표시 크기 |
|---|---|---|
| 칩 (기본·특수·떠돌이) | **32×32** | **64px** (2배) |
| 보드 셀 | — | **72px** (칩 64 + 여백 8) |
| **별자리 카드** | **36×52** | **72×104px** (2배) |
| 동반성 아이콘 | 16×16 | 32px |
| **ORION (M42)** | **60×78** | **120×156px** (2배) |
| 문양 5종 (칩 내부) | 16×16 | 칩 중앙에 배치 |

> **칩이 16×16 → 32×32로 커진 이유**: 반지름 8px에 디테일 4겹을 넣으면 중앙에 3px만 남아
> 문양이 사라진다. 32×32의 **중앙 16×16이 정확히 기존 문양 크기**이므로,
> 칩을 키우면서 문양 5종은 한 장도 다시 그리지 않았다.

#### 칩 구조 (바깥에서 안으로)

| 겹 | 내용 | 색 |
|---|---|---|
| ① | 가장자리 노치 6개 (60° 간격) | **해당 문양의 밝은 변형색** |
| ② | 안쪽 링 1px | 바탕색의 어두운 변형 |
| ③ | 점선 원 1px | 밝은 색, 일정 간격 |
| ④ | 중앙 문양 | 기존 16×16 픽셀맵 그대로 |

노치를 크림색이 아니라 **문양별 밝은 색**으로 칠하면 카지노 칩 인상이 옅어지고,
별빛이 새어나오는 인상이 생기며, **특수 조각의 좌우 분할이 테두리에서도 드러난다.**

**특수 조각 합성**: 16열에서 자른다. 링·노치가 좌우 대칭이라 그대로 이어진다.
중앙 문양은 기존 규칙대로 좌 8열 + 우 8열.

### 11-5. 별자리 12종 — 세로 직사각 카드

**칩이 아니다.** 36×52 픽셀맵의 **트럼프 카드 형태**이며, 표시 크기는 72×104px다.

> 32×48 → 36×52로 키운 이유는 **프레임에 2px를 확보하면서 성도 영역(26×40)을 그대로 유지**하기 위함이다.
> 성도가 줄면 별자리 형상이 무너진다.

> ⚠️ **"판정 패턴 도식" 안은 폐기됐다.** 조건의 기하 도식(점 N개를 축 방향으로 배열)은
> 판독은 되지만 우주 테마를 잃는다. 카드는 **실제 성도(星圖) 이미지**를 싣는다.

#### 카드 구성

| 요소 | 내용 |
|---|---|
| 프레임 | **2px** — 테두리 선 + 성좌 장식 + 둥근 모서리 |
| **배경** | **별하늘 픽셀 아트** (아래 참조) |
| 중앙 | 해당 별자리의 **실제 성도** |
| 별 | 십자 발광 (밝은 코어 + 4방향 팔), 등급별 크기·밝기 차등 |
| 연결선 | 별보다 어두운 청색 계열 |

#### 배경 — 카드마다 다른 별하늘

| 요소 | 내용 |
|---|---|
| 바탕 | 어두운 남보라 |
| 성점 | 불규칙 산포 — **1px 점 · 2px 십자 · 드물게 밝은 별** |
| 성운 얼룩 | 1~2군데, **카드 고유 색의 아주 어두운 변형** |

**12종이 각자 다른 하늘을 갖는다.** 배치는 별자리 인덱스로 시드된 난수에서 나오므로
카드를 다시 그려도 같은 하늘이 나온다(CLAUDE.md §8). 열두 장을 늘어놨을 때
한 배경의 복사본 열두 개로 보이면 안 된다.

> 🚫 **5×5 판정 격자 좌표계 안은 폐기됐다.** 성도 뒤에 게임 보드를 겹쳐 판정 셀을
> 강조하는 방식은 판독에는 도움이 되지만, 카드가 **성도가 아니라 도표**가 된다.
> 판독 문제는 아래처럼 텍스트로 푼다.

#### 프레임 장식 — 2톤 성좌

카드 고유 색에서 두 톤을 만든다.

| 톤 | 만드는 법 | 쓰는 곳 |
|---|---|---|
| 진한 톤 | 고유 색을 배경 쪽으로 약간 눌러서 | 테두리 선, 별을 잇는 연결선 |
| 연한 톤 | 진한 톤에 흰색을 섞어서 | 별의 코어, 모서리 앵커 |

테두리 둘레 전체에 별을 띄엄띄엄 놓고 연결선으로 잇는다.
**네 모서리의 별은 더 크고 밝게** 두어 앵커 역할을 시킨다.
12종이 각자 고유 색을 쓰되 **장식 패턴은 완전히 동일**하다 — 카드가 한 세트로 보여야 한다.

#### ★ 밝기 위계 (절대 규칙)

> **프레임 별의 최대 밝기 < 성도 별의 평균 밝기.**
> 프레임이 성도보다 밝으면 시선이 테두리에 뺏겨 카드를 읽을 수 없다.

이 조건은 **눈대중이 아니라 계산으로 강제**한다. 연한 톤은 카드의 성도 평균 밝기의
80% 아래로 내려갈 때까지 배경 쪽으로 단계적으로 눌린다. 테스트가 12종 전부를 검사한다.

> ⚠️ 그래서 **진한 톤은 고유 색 원본 그대로가 아니다.** 청록·호박처럼 원래 밝은 색조는
> 원본 그대로 두면 안쪽 성도와 밝기가 맞먹어 위계가 깨진다.
> 위 ★ 조건과 "원본 그대로" 지시가 충돌하므로 **★를 우선**했다.
> 색조는 유지되므로 축 식별에는 영향이 없다.

성도 자체는 **전 카드 청백색으로 통일**한다. 별자리 형상은 어느 축이 발동하는지를
전혀 말해주지 않으므로, 축 구분은 **프레임 색**이 전담한다.

#### 축 색상 코딩 — 프레임 색으로 유지

| 계열 | 별자리 | 프레임 색 |
|---|---|---|
| 세로 | 양자리 · 염소자리 · 궁수자리 | **청록** |
| 가로 | 천칭자리 · 물고기자리 · 사자자리 | **호박** |
| 대각 | 쌍둥이자리 · 황소자리 · 전갈자리 | **자홍** |
| 도형 | 물병자리 · 처녀자리 | **연보라** |
| 전역 | 게자리 | **수소적색** |

> 이 색 코딩은 밸런스와도 직결된다. 게임 시작 시 플레이어는
> **양자리(세로) / 천칭자리(가로)** 중 하나를 고르는데(10-3절),
> 축이 색으로 즉시 구분되지 않으면 그 선택이 무의미해진다.

#### ★ 판독성은 텍스트 병기로 해결한다 (절대 규칙)

성도는 "이게 무슨 별자리인가"만 말할 뿐 **연속 몇 개인지, 배율이 얼마인지는 말하지 못한다.**

> **양자리(세로 3연속)와 천칭자리(가로 3연속)는 그림만으로 절대 구분할 수 없다.**
> 두 규칙은 축만 다른데, 두 성도는 서로 닮은 구석이 전혀 없다.
> 격자 좌표계를 폐기한 이상 이 격차를 그림으로 메울 방법은 없다.

따라서 **카드를 단독으로 표시하지 않는다.**

```
[카드 이미지]
 궁수자리
 세로 5연속
 ×2.5
```

| 규칙 | 내용 |
|---|---|
| 표시 단위 | 카드 이미지 + **이름 · 조건 · 배율**이 항상 한 덩어리 |
| 구현 강제 | `ui/ConstellationCard.tsx` 하나만이 카드를 화면에 올린다. 이 컴포넌트는 텍스트를 뗄 수 없다 |
| 금지 | `PixelSprite`에 카드 픽셀맵을 직접 넘겨 단독 표시하는 것 |
| 문자열 출처 | `CONSTELLATION_RULES` · `CONSTELLATION_MULTIPLIERS`에서 파생 |

카드와 엔진이 서로 다른 규칙을 말하는 일이 없어야 한다.

> 성도 좌표는 **양식화된 성도**다. 이 크기에서 각 별자리의 알아볼 수 있는 몸짓을 살린 것이지
> 실측 천문 좌표가 아니다.

### 11-6. 떠돌이 칩 외형

**다른 조각과 완전히 동일한 칩 레이아웃**을 쓴다 — 노치 6개, 안쪽 링, 점선 원, 중앙 문양.
보드 위에서 이것은 별종이 아니라 **조각 하나**여야 하므로, 실루엣으로 구별하지 않는다.

| 요소 | 내용 |
|---|---|
| 레이아웃 | 기본 조각과 동일 (11-4절 4겹 구조) |
| 바탕 | **무지개 그라데이션** — 정해지지 않은 상태의 시각화 |
| 중앙 문양 | **왕관** (16×16, `pixels.ts`) |
| 링·문양 색 | 어두운 색 — 무지개 어느 구간에서도 대비가 확보된다 |

- 무지개는 **Ginan(적) → Gacrux(녹) → Imai(청) → Mimosa(자)** 를 잇는 연속 그라데이션이다.
  **Acrux(검정)는 제외한다** — 빛의 색이 아니고, 밴드로 넣으면 칩을 가로지르는 죽은 띠가 된다.
- 테두리·노치·점선 원도 무지개를 따라간다. 흰 테두리로 두면 노치와 점선이 칩 표면의 1/3이라
  무지개를 통째로 삼킨다.
- 6번째 기본 문양처럼 보이면 안 된다 → **왕관**이 그 역할을 한다.
  다섯 문양 중 어느 것도 아니면서 "무엇이든 될 수 있다"를 말한다.

> 초기안(육각 결정 실루엣)은 폐기했다. 실루엣을 다르게 하면 혼동은 사라지지만
> 보드 위에서 혼자 튀어 **조각이 아니라 이물질로 읽힌다.**

> Rare/SR/Epic/Mythic/Legendary 프레임이 필요한데, 32색을 지금 다 쓰면 자리가 없다.

> ⚠️ **Acrux(`#2B2B38`) 주의**: 어두운 배경 위에서 묻힌다.

#### 성점 · 연결선 · 카드 프레임 색의 출처

**새 색을 추가하지 않았다.** 티어 프레임 5색은 손대지 않고, 아래처럼 기존 배분 안에서 겸용한다.

| 카드 요소 | 쓰는 색 | 원래 용도 |

성운 계열이 배경과 축 코딩을 겸하는 것은 의도다. 축 구분에 필요한 5개의 뚜렷한 색조는
실제 성운의 색 분포와 정확히 같은 범위이므로, 코딩이 **범례가 아니라 천문**으로 읽힌다.

### 11-8. ORION 디자인 지침

**역할**: 플레이 중 해설·반응을 담당하는 동반자다. 상점 딜러는 иєвυℓα(11-9절)가 맡는다.
디자인 지침 자체는 아래 그대로 유지한다.

- 인간형이되 **머리와 팔만** 사람과 유사한 신체 구조
- 몸통 아래는 오리온 대성운의 형상 — 붉은 수소 발광(Hα) + 푸른 반사성운의 그라데이션
- 귀여운 도트 캐릭터 톤 (위협적이지 않게)
- 표정 4종: 기본 / 놀람 / 만족 / 거래
- **60×78 픽셀맵**은 유일하게 손이 많이 가는 부분 → **P4 단계에서 별도 집중 작업**

> 초기 규격 48×64(96×128 표시)에서 **60×78(120×156 표시)**로 키웠다.
> 참조 영상의 캐릭터가 화면 높이의 약 24%를 차지하는데, 96×128은 630px 캔버스에서 20%에 그쳐
> 해설자가 화면 구석의 장식으로 읽혔다. 156px는 캔버스 높이의 24.8%다 (11-10절).

### 11-10. ★ 화면 레이아웃 — 고정 캔버스 (절대 규칙)

**게임 화면은 1120×630 고정 캔버스다. 유동 웹 레이아웃으로 되돌리지 않는다.**

#### 왜 고정인가

유동 레이아웃에서는 크기가 픽셀로 박힌 요소(보드)만 제자리를 지키고 나머지는 flex 여백을 따라
흩어진다. 2560px 모니터에서 보드는 360px 그대로인데 손패·정산·ORION이 사방으로 밀려나
**참여자마다 다른 화면을 보게 된다.** 요소를 개별 이동해서는 해결되지 않는다 — 레이아웃이
유동이기를 그만두어야 한다. 부스는 서로 다른 노트북 3대 이상으로 운영되므로(12-2절)
**모든 기기에서 같은 그림**이 나오는 것이 요구사항이다.

#### 방식

| 항목 | 값 |
|---|---|
| 논리 캔버스 | **1120×630** (16:9) |
| 배치 | 전 요소 **절대 좌표** |
| 창 맞춤 | 컨테이너에 `transform: scale()` |
| 배율 | `min(창폭/1120, 창높이/630)`을 **정수로 내림** |
| 남는 영역 | `void` 색 레터박스 |
| 스프라이트 | `image-rendering: pixelated` 유지 |

> ⚠️ **배율을 정수로 내리는 이유**: CLAUDE.md §7과 11-4절이 **정수배 스케일만** 허용한다.
> 1366×768의 원시 배율은 1.22, 2560×1440은 2.28이다. 소수배로 그리면 32×32 칩이
> 픽셀 경계에 걸치지 않아 도트 격자가 무너진다. 내림하면 각각 **1배·2배**가 되며,
> 이는 레이아웃이 애초에 설계된 배율이다.
>
> 캔버스보다 **작은 창**에서만 예외로 소수배를 쓴다. 내림하면 0이 되기 때문이며,
> 잘려 보이는 것보다 작게라도 전부 보이는 편이 낫다.

## 12. 부스 운영 제약 ⚠️ (1인 운영 확정)

개발자 겸 운영자가 **1명**이다. 이는 게임 설계에 직접 영향을 준다.

### 12-1. 처리량 계산

| 조건 | 시간당 참여자 |
|---|---|
| 풀버전 40분 × 노트북 1대 | **1.5명** |
| 풀버전 40분 × 노트북 3대 | 4.5명 |
| 부스판 15분 × 노트북 3대 | **12명** |

GBL은 **참여 중학생의 투표**로 순위가 정해진다.
표를 던질 사람 수가 곧 점수이므로, **처리량이 곧 성적**이다.

### 12-2. 그래서 필요한 것

1. **완전 자립형 튜토리얼** — 운영자가 옆에 붙어 설명하지 않아도 시작할 수 있어야 한다.
   1인 운영에서는 이게 선택이 아니라 필수다.
2. **노트북 3대 이상 동시 운영** — 브라우저 실행이므로 대수 확장은 자유롭다.
3. **부스판(3라운드 ≈ 15분) 분기** — Phase 7에서 최종 판단.
   풀버전 코드에서 `TOTAL_ROUNDS`와 `TARGET_SCORES`만 교체하면 되도록 설계한다.
4. **원클릭 리셋** — 다음 참여자를 위해 즉시 초기화.
5. **로컬 리더보드** — 운영자 개입 없이 경쟁 심리 유발.

### 12-3. 설계 반영

`src/core/config.ts`에 부스 모드 프리셋을 함께 정의한다.

```ts
export const MODE_PRESETS = {
  full:  { TOTAL_ROUNDS: 8, TARGET_SCORES: [490, 630, 640, 880, 1080, 1250, 1330, 1530] },
  booth: { TOTAL_ROUNDS: 3, TARGET_SCORES: [490, 630, 640] },
};
```

> 목표치는 10절이 원본이고 P2-B에서 역산 확정됐다. 이 블록은 **구조**를 보이기 위한 것이므로,
> 수치를 여기서 고치지 말고 10절과 `config.ts`를 따라간다.

### 12-4. 부스 모드의 밸런스 철학은 풀버전과 정반대다

| | 풀버전 | 부스판 |
|---|---|---|
| 목표 클리어율 | **20 ~ 30%** (도전) | **70% 이상** (만족) |
| 최적화 대상 | 재도전 욕구 | **투표** |

부스 참여자는 단 한 번 플레이하고 투표한다. 실패하고 떠나면 표를 잃는다.

> **판정 기준은 개별 숫자가 아니라 클리어율이다.**
> 초기 문구는 "상향 금지"였으나, 이는 개별 목표값이 아니라 **난이도**를 뜻한다.
> 실제 확정안에서 R2는 500 → 630으로 올랐지만, 기존 300·500은 바닥값 600보다 낮아
> 아무도 탈락시키지 못하는 장식이었고 실질 관문은 R3(800) 하나뿐이었다.
> R3를 640으로 크게 낮춘 결과 greedy 클리어율이 **28.4% → 72.3%** 로 개선됐으므로
> 규칙의 취지는 지켜졌다.
>
> (이 두 수치는 떠돌이 가격 10 시점의 측정이다. 무상 지급까지 반영한 최종값은 **85.3%** 다 — 13-6절.)

### 12-5. ★ 부스판 WAGER 보정 원칙 (신규)

풀버전 측정에서 WAGER 정답률 0% ↔ 100%의 클리어율 차이가 **27.0%p**로 나타났다.
학습 행동이 승패에 유의미해진 것은 성과지만, **부스판에 그대로 적용하면 재앙이다.**

> 부스 참여자는 **확률을 배우러 온 중학생**이다.
> 확률 문제를 못 맞혀서 탈락한다면, 게임이 가르치려는 바로 그 대상을 걸러내는 것이다.

따라서 두 버전에 **서로 다른 원칙**을 적용한다.

| | 풀버전 | 부스판 |
|---|---|---|
| WAGER의 역할 | 승패를 가르는 실력 요소 | **순수 상방(bonus)** |
| 목표치 보정 기준 | smart 기본 정답률(80%) 기준 | **WAGER 정답률 0% 기준으로 70% 클리어** |
| 근거 | 반복 플레이어 대상 | 1회 플레이 + 학습 대상자 |

**즉 부스판 목표치는 "확률을 하나도 못 맞혀도 70%가 클리어"하도록 잡는다.**
확률을 잘 맞히는 학생은 더 여유롭게 클리어할 뿐, 못 맞히는 학생이 탈락하지는 않는다.
이것이 교육용 게임과 실력 게임을 가르는 지점이다.

#### ✅ P2-B 측정 결과 — 현행 목표치가 이미 원칙을 만족한다

| tier (sum) | WAGER 0% | WAGER 50% | WAGER 100% |
|---|--:|--:|--:|
| greedy | **71.3%** | 85.0% | 87.2% |
| smart | 94.7% | 94.2% | 94.2% |

`[490, 630, 640]` 그대로 기준을 충족하므로 **재역산하지 않는다.**
부스판에서 WAGER는 71.3% → 87.2%의 **순수 상방**으로 작동한다.

대조군으로 풀버전은 smart 기준 4.2% → 40.4%(+36.2%p)다. 같은 장치가 버전에 따라
전혀 다른 역할을 하며, 그것이 이 절을 따로 둔 이유다.

### 13-1. P2 시뮬레이터가 반드시 포함해야 할 케이스

**① 단일 문양 도배 보드 + 물병자리·처녀자리 동시 보유**

> ✅ **해소** (`tests/gdd13-1.test.ts`): ㅅ자 12개 + ㅗ자 12개가 동시 발동해도
> 물병+처녀 2,432점 vs 궁수+사자 1,250점으로 **1.95배**에 그친다. 네 별자리 전부라도 3,662점.

> ✅ **해소** (`tests/gdd13-1.test.ts`): 칸 기여 최상 50 / 보통 30 / 최악 10점·턴.

### 13-4. 떠돌이 조각 가격 — 교육적 근거로 인하

측정 결과 스타더스트 1당 기여가 최상 2.5 / 보통 1.5 / 최악 0.5점·턴으로,
기본 조각(3.3)보다 **나쁘다.** 가격 20은 순수 효율로는 명백한 과다다.

그런데 여기엔 점수 효율보다 중요한 이유가 있다.

> **떠돌이 조각을 사지 않으면 `DRIFT ORACLE`(GDD 8-3)이 게임 내내 한 번도 발동하지 않는다.**
> 이 장치는 교과서 Ⅲ-2 **기댓값**을 가르치는 유일한 수단이며,
> 4개 학습 장치 중 확률 개념이 가장 직접적으로 드러나는 순간이다.

즉 이 아이템의 가격은 **밸런스 문제가 아니라 학습 노출률 문제**다.
학생이 "비싸서 안 삼" → 기댓값 단원이 통째로 사라진다.

#### P2-B 결과: 인하는 과잉 교정이었다

| 지표 | 가격 20 | 가격 10 |
|---|---|---|
| 구매율 | 28.3% | **98.6%** |
| 미구매 시 클리어율 | — | **0.0%** (전 등급) |

학습 노출률 목표는 달성했으나, **선택이 아니라 세금**이 됐다.
98%가 첫 상점에서 즉시 구매하므로 "게임당 1회 한정"이라는 희소성 연출도 무의미하다.
더 심각한 것은, 이해 못 하고 안 산 학생은 **그 시점에 이미 게임이 끝난다**는 점이다.

#### 확정: 구매가 아니라 무상 지급

**иєвυℓα와의 첫 만남에서 떠돌이 조각을 무상으로 지급**한다.

| 효과 | 내용 |
|---|---|
| DRIFT ORACLE 발동률 | 98.6% → **100%** |
| 가짜 선택지 제거 | 스타더스트가 실제 의사결정에 쓰인다 |
| 목표 곡선 유효성 | 시뮬 전제(98.6% 보유)와 사실상 동일 → **재보정 불필요** |
| 서사 | 딜러가 첫 거래 기념으로 건네는 선물 |

`SHOP_PRICES`의 떠돌이 항목을 제거하고, 상점 진열에서도 뺀다.

> **P4-A 보강**: `SHOP_SLOTS.drifterChips`가 남아 있던 것을 함께 제거했다.
> `rollStock`이 읽지 않아 무해했지만, 죽은 설정값은 나중에 되살아나 이 절을 조용히 깨뜨린다.
> 떠돌이는 **재고가 아니라 선물**이므로 진열 칸이라는 개념 자체가 없어야 한다.
> 9-3의 상점 구성 박스에서도 떠돌이 줄을 뺐다 — 지급은 첫 방문 시 `grantDrifter`가 한다.

### 13-5. 🚨 R1은 플레이어 행동과 무관하다

R1 점수는 **모든 등급에서 정확히 600점, 표준편차 0**이다.
별자리는 R1 클리어 후 상점에서만 살 수 있는데, 별자리가 없으면 라인이 발동하지 않아
점유 칸수 × 10의 합(40+80+120+160+200)만 남기 때문이다.

| 문제 | 영향 |
|---|---|
| 실력·확률 판단이 점수에 **0** 반영 | 첫 5턴 동안 피드백 루프가 없다 |
| 첫인상 구간 | 부스 참여자가 게임을 판단하는 바로 그 5턴 |
| 별자리 개념 미노출 | 게임의 핵심 시스템을 R2에야 처음 본다 |

#### 처방: 시작 별자리 1개 지급

게임 시작 시 **양자리(세로 3연속, ×1.2) / 천칭자리(가로 3연속, ×1.2) 중 1개를 선택**하게 한다.

- 두 별자리는 배율이 같고 축만 다르다 → 밸런스 영향 없이 **"세로냐 가로냐"** 라는 첫 의사결정이 생긴다
- 별자리 시스템을 R1부터 체험한다
- R1 점수에 변동성이 생겨 배치 실력이 즉시 피드백된다
- 보유 한도 4개 중 1칸을 채우고 시작한다

> 이 변경은 R1 목표치 재산정을 동반한다. 13-3절 기준에 함께 반영한다.

### 13-6. P2-B 최종 측정 (조합당 1,000회 · 시드 20260101 · 동반성 비활성)

전문은 `sim/out/results.md`. P2-A 규칙 기준선은 `sim/out/results-p2a-baseline.md`에 보존했다.
아래는 모두 **떠돌이 무상 지급(13-4절) + 시작 별자리(13-5절)** 를 반영한 최종 규칙 기준이다.

#### 조건 판정

| # | 조건 | 측정값 | 판정 |
|---|---|---|---|
| 1 | smart 풀버전 20~30% | **28.1%** | ✅ |
| 2 | greedy 부스판 ≥70% | **85.3%** | ✅ |
| 3 | 전 라운드 ≤ 기계적 상한 70% | 최대 68.6% (R1) | ✅ |
| 12-5 | **WAGER 0%에서도 greedy 부스판 ≥70%** | **71.3%** | ✅ |

#### ① 부스판 WAGER 민감도 — 원칙이 지켜졌다 (미해결 #19 해소)

| tier (sum) | WAGER 0% | WAGER 50% | WAGER 100% | 0%→100% |
|---|--:|--:|--:|--:|
| greedy | **71.3%** | 85.0% | 87.2% | +15.9%p |
| smart | 94.7% | 94.2% | 94.2% | −0.5%p |

**부스판에서 WAGER는 순수 상방이다.** 확률을 하나도 못 맞혀도 greedy는 71.3%가 클리어하고,
잘 맞히면 87.2%로 올라간다. 목표치 재역산은 불필요하다.

smart가 −0.5%p로 평평한 것은 오차 범위다 — smart는 WAGER 없이도 부스판을 94% 클리어하므로
스타더스트가 더 들어와도 더 넘을 것이 없다.

풀버전은 정반대다. smart 기준 4.2% → 40.4%(**+36.2%p**)로, WAGER가 승패를 지배한다.
**두 버전에 서로 다른 원칙을 적용한 12-5절의 판단이 수치로 정당화됐다.**

#### ② 떠돌이 무상 지급의 실제 효과 (미해결 #18 해소)

| 지표 (sum) | 가격 10 | 무상 지급 |
|---|--:|--:|
| greedy 부스판 클리어율 | 72.3% | **85.3%** |
| smart 풀버전 클리어율 | 22.0% | **28.1%** |
| 떠돌이 칸 기여 (greedy) | 53.3점/턴 | **66.5점/턴** |
| 떠돌이 칸 기여 (smart) | 81.2점/턴 | **103.6점/턴** |

> ⚠️ **"재보정 불필요"는 절반만 맞았다.** 보유율은 98.6% → 100%로 거의 그대로지만,
> **10 스타더스트가 통째로 다른 데 쓰이게 됐다.** 그건 별자리 하나 값이다.
> 그 결과 별자리를 하나 더 사고 → 라인이 늘고 → 떠돌이 칸 기여까지 25% 올라갔다.

그래도 세 조건은 모두 유지된다. 다만 **smart 풀버전 28.1%는 20~30% 구간의 상단**이다.
P4에서 동반성이 들어오면 30%를 넘길 가능성이 높다 → 미해결 #14(P4 이후 재측정)에서 처리한다.

#### ③ 시작 별자리는 여전히 밸런스의 전제다

| (sum) | 시작 별자리 없음 | 있음 |
|---|--:|--:|
| greedy 부스판 | 62.1% | **85.3%** |
| smart 풀버전 | 18.8% | **28.1%** |
| R1 표준편차 (greedy) | **0** | **28** |

#### ④ 배율 스택 — `sum` 확정 유지

smart 풀버전: `sum` 28.1% · `product` 25.2% · `additive_delta` 14.2%.
부스판은 세 방식이 사실상 동일(85.1~85.3%)하다 — R1~R3에서는 한 라인에 별자리가 둘 이상 걸리는 일이 드물다.

#### ⑤ 미해결 #20 — 풀버전 실력 격차는 그대로

| tier | 풀버전 | 부스판 |
|---|--:|--:|
| random | 0.0% | **10.7%** |
| greedy | **2.4%** | 85.3% |
| smart | 28.1% | 94.1% |

무상 지급으로 greedy 풀버전이 1.3% → 2.4%로 올랐지만 여전히 사실상 클리어 불가다.
